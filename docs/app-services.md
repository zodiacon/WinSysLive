# App-wide machinery

What every view and dialog relies on: Copy and Export, the ACL editor, highlighting, the tray icons and window options, startup, updates and settings files, symbols and DPI. Read the entry before changing it.

- **Copy** (`ID_EDIT_COPY`: Ctrl+C, the toolbar's Copy button with `IDI_COPY`): the frame handles it first when an edit box has the focus (a filter: `WM_COPY`, `OnEditCopy`), else it goes to the active view's `ALT_MSG_MAP(1)` as before; each view copies its selection (the shown columns, tab separated), the Processes view the focused lower pane page's row instead of the process when a page has the focus (the pages' `Copy`). The frame enables the command while idle from `CMainFrame::CanCopy`: an edit box's selection, else the active view's `IView::CanCopy` (the views with a Copy: a selected row; Object Manager the tree's directory while the tree has the focus; Processes the process, or the focused page's selection, `CanCopy` of the pages; default false, so the Performance tab disables it).
- **Export** (`ListExport.*`): File > Export List (Ctrl+S) saves, and Copy All Rows (Ctrl+Shift+C) copies, a list view of the active view's that has the focus (the lower pane's pages too), else the view's `IView::GetExportList` (a view without a list may export its own way: `IView::CanExport` enables the command, which reaches the view's `ALT_MSG_MAP(1)` first, as the History tab saves its log): the shown columns in display order and every row, read with `LVM_GETITEMTEXT` (owner-data and callback lists answer as they would to paint). A TreeListView leaves column 0's text out of its inner list (it draws that column itself), so views with one answer `IView::GetTreeColumnText` from `CTreeListViewCtrl::GetCellText` and `GetVisibleItem`. CSV (RFC 4180 quoting) or tab-separated text, UTF-8 with a BOM.
- **ACL editor** (`ObjectSecurity.*`): `CObjectSecurityInfo` is the `ISecurityInformation` the handle sheet, the process sheet's Security page and the Token page's Security... button give the system's ACL editor: an object's descriptor through WinSys `ObjectInspector::GetSecurity`/`SetSecurity`, read-only without WRITE_DAC in the handle's access and the owner without WRITE_OWNER (`Open` tries READ_CONTROL with both, with WRITE_DAC, then alone); the rights it lists are the type's (`AccessMaskDecoder::GetSpecificRights`) and the standard ones, mapped through the type's generic mapping (`ObjectInspector::QueryTypeStatistics`). `SetSecurityTabIcon` puts the system's shield on the editor page's tab. `CAclDialogTheming`, a member of each sheet installed once it exists, gives the editor's own dialogs (Advanced, a permission entry, Select User or Group, `EditSecurity`'s sheet) dark title bars: a CBT hook on the thread applies `WTLHelper::ApplyMode` to each window the sheet owns (directly or through such a dialog) from a zero-delay thread timer after its first activation, as a dialog builds its contents after it's activated. The Advanced dialog is DirectUI: its buttons, tab and edges stay light in dark mode (suspending WTLHelper's hook didn't make it consistent: the detoured system colors keep its background dark).
- **Highlighting** (`Highlight.*`, `HighlightDlg.*`): how long new items stay green and exited ones (exited, closed, unloaded, removed) red, everywhere: the Processes view, the lower pane's and the sheets' Threads, Modules and Handles pages, the Network tab and TCP/IP pages (`ConnectionRows::Merge`'s `newTicks` and `closedTicks`), Kernel Modules, RPC/ALPC (new rows only), Object Manager, Disk and Services (new services; a state change keeps its own two updates, and deleted services go at once). Options > Highlighting... (`CHighlightDlg`) sets the `NewHighlight` and `ExitedHighlight` settings, in seconds (0 to 60; zero turns it off, exited items then going at once), and says how many updates that is; the views count updates, so `Highlight::Set` converts the seconds at the update interval (rounded, at least one), called by the frame at startup, after the dialog and when the interval changes (`SetUpdateInterval`). `Highlight::NewTicks`/`ExitedTicks` are atomics, read on the property sheets' threads too. Where the descriptions below say new rows are green for two refreshes and gone ones red once, those are the defaults at the default interval. An exited item still shown counts down its own refreshes (`ExitedTicks`, `ClosedTicks`, `UnloadedTicks`, `RemovedTicks`, `GoneTicks`, or the pages' `m_Exited`, `m_Unloaded`, `m_Closed` lists).
- **Tray and window options** (Options menu, `TrayIcon.*`, `TrayIcons.*`, `TrayIconsDlg.*`): up to five notification area icons, CPU, I/O, commit charge, physical memory and network (`TrayIconKind`), each a graph (one column per refresh, newest on the right; percentages to 100, the rates to the largest shown, at least 100 KB/s) in its own color on a dark square, with the details in its tooltip (a text style, the current value in the icon, was tried and dropped: a 16-pixel icon holds too little to read). Options > Tray Icons... (`CTrayIconsDlg`, also in the tray menu: a check box per icon, the template's `IDC_TRAY_SHOW` + kind) sets the `TrayIcons` setting (`Key:Mode` pairs, `Graph` or `Off`, `CTrayIcons::Load`/`Save`; keys must not change); while it's empty the old `TrayIcon` setting (on by default) means the CPU graph alone, and `Save` keeps `TrayIcon` set while any icon is shown, for older versions. `CTrayIcons` owns the icons (ID: kind + 1, added in kind order, so the callback's wParam tells them apart; every one acts the same) and samples, from `CMainFrame::Refresh`, only what's shown: the CPU percentage the frame computes from the Idle process (none on the first refresh), `SYSTEM_PERFORMANCE_INFORMATION`'s I/O transfer counts (rates over QPC time, as the Performance tab's I/O page), commit charge and limit and available pages (physical memory as total minus available), and a WinSys `NetworkTracker` over the adapters, held only while the Network icon is shown. The icons are added again on `TaskbarCreated` (Explorer restarted, `AddAgain`). A left click brings the window back; the right-click menu has Show/Hide, Pause Updates, Always on Top, Tray Icons... and Exit. Minimize to Tray (`MinimizeToTray`) hides the window when it's minimized (`WM_SIZE`), only while an icon is shown, and turning the last icon off brings a hidden window back (`ApplyTrayIcons`). Close to Tray (`CloseToTray`, off by default, also only while an icon is shown) does the same for the close button, Alt+F4 and the taskbar's Close Window: `OnSysCommand` takes `SC_CLOSE`, so Exit, the restarts and other programs' `WM_CLOSE` (`taskkill`) still exit, as does the session ending. It minimizes before hiding, leaving the state Minimize to Tray leaves: an owner hidden directly would keep its owned Find dialog on screen, and `OnShowObjectPath` restores only an iconic window. Exiting from the tray saves a minimized placement; the next start shows the window as it was before (`WPF_RESTORETOMAXIMIZED`: maximized). Always on Top (`AlwaysOnTop`) is `HWND_TOPMOST`, for the process property sheets too (unowned windows on threads of their own, which would otherwise sit under the main window: a sheet reads the setting when it opens, and the command sets the open ones with `SetProcessPropertiesTopmost`, asynchronously, as a sheet may be busy in a query); its menu items have `IDI_PIN` (`pin.ico`), the tray menu's too (`ShowTrayMenu` calls `InitMenu`, so Pause Updates has its icon there as well; a checked item with an icon is drawn framed, without a check mark). Global Hotkey... (`CHotKeyDlg`, `HotKeyDlg.*`; `GlobalHotKey.h`, the `GlobalHotKey` setting: the hotkey control's value, 0 for none, the default) registers a key with `RegisterHotKey` on the frame (`SetGlobalHotKey`, at startup and from the dialog, `MOD_NOREPEAT`; Ctrl or Alt required, so the control's rules turn a plain key or Shift and a key into Ctrl+Alt and the key); `WM_HOTKEY` (`OnHotKey`) brings the window back in front (`RestoreWindow`, then a modal dialog of the frame's, `GetLastActivePopup`) or, when it's in front already, minimizes it (to the tray with Minimize to Tray). A key another program has registered is refused in the dialog (`ERROR_HOTKEY_ALREADY_REGISTERED`), which stays open, and the old key stays registered; a saved key taken since stays unregistered (the setting is kept). Tested: Ctrl+Alt+F11 held by another thread was refused, then registered, restored a minimized window to the front and minimized it again, and was released at exit. Single Instance (`SingleInstance`, off by default): starting the app again brings the running instance to the front, as below, and exits; `ActivateRunningInstance` runs after the settings are loaded, and Run as Administrator passes `/restart`, which skips it, as the elevated instance starts while this one still runs. Replace Task Manager (enabled only when elevated) writes or deletes the `Debugger` value of `taskmgr.exe`'s Image File Execution Options in HKLM; it's checked when that value names this exe (Process Explorer's doesn't count). Windows then starts the app with taskmgr.exe's path as an argument (unelevated, as the "debugger" of a program that elevates itself), so `ActivateRunningInstance` in `WinSysLive.cpp` posts `CMainFrame::ActivateMessage` (registered) to a running instance (found by the frame's fixed class name, `WinSysLiveFrame`) and exits; that message and `TaskbarCreated` are let through UIPI (`ChangeWindowMessageFilterEx`), since the running instance may be elevated. Without a running instance, `StartElevatedAsTaskManager` starts the app elevated, as Task Manager starts, and exits: through "WinSysLive Task Manager (<user>)" (`CMainFrame::TaskManagerTaskName`), an on-demand task at the highest run level (WinSys `LogonTask::RegisterOnDemand`, no trigger, parallel instances) starting the exe with `/taskmgr`, which turning the option on registers (off deletes it; an elevated start registers it again when it's missing or names another exe, for another user or a moved exe) and `LogonTask::Run` starts without a UAC prompt (skipped when it names another exe); without it, an administrator's limited token gets the `runas` prompt; a standard user, a declined prompt or a failure leaves this instance running unelevated. `ASFW_ANY` lets the task's instance take the foreground.
- **Update interval** (View > Update Interval, `UpdateInterval` setting, in ms): 0.5, 1, 2 and 5 seconds (`s_Intervals`), or Other... (`ID_UPDATEINTERVAL_OTHER`, `CUpdateIntervalDlg`, `UpdateIntervalDlg.*`): seconds with up to three decimals, a dot or a comma, 0.1 to 60 (`IntervalText.h`, tested; text that isn't one keeps the dialog open with a note). `SetUpdateInterval` takes any interval in that range (else 1 second): a fixed one gets its radio mark (`UISetRadioMenuItem` over the four), any other checks Other, whose text then shows it ("Other (0.25 s)..."). Other is checked rather than given a radio range because WTL keeps an item's text and its radio range in one union (`_AtlUpdateUIData`: a range set on Other was read as its text, a crash), and its item is `MFT_RADIOCHECK` (set in `OnCreate`; WTL keeps the type when it sets the text), so the mark is a bullet all the same; a range from 0.5 Seconds to Other would also take in the priority commands, whose IDs lie between. The status bar's tooltip says the interval with `IntervalText::Seconds`.
- **Status bar** (`CMainFrame::InitStatusBar`, `s_Panes`, the widths from the panes' string resources): the default pane (the views' status text), Updates, Processes, Threads, CPU (the Idle process's, relative to the previous update) and Administrator or Standard User. Updates (`ID_PANE_UPDATES`, `UpdatePausePane`) shows the updates' state: a play icon (`IDI_RUN`) and "Updating" while they run, a pause icon (`IDI_PAUSE`) and "Paused" while they don't (View > Pause Updates, the toolbar's button, which shows the action instead, the tray menu), with a tooltip naming the interval; the icons are loaded for the DPI and the pane's width set for the icon and the longer text, both again after a DPI change (`SetPanes` sets the widths from the strings). A click on it pauses or resumes (`NM_CLICK`, `OnStatusBarClick`): posted as `ID_VIEW_PAUSE`, as pausing changes the parts while the status bar is still handling the click, which crashed comctl32 when done at once. The dark mode's painting (WTLHelper's) draws a part's icon before its text, as the native control does. Checked from outside with messages that carry no pointer (`SB_GETTEXTLENGTH`, `SB_GETICON`): a status bar's pointer messages (`SB_GETRECT`, `SB_GETTEXT`) aren't marshaled across processes, and sending one from a script crashes the app.
- **Record from Startup** (Options menu, `ID_OPTIONS_RECORDFROMSTARTUP`, the `RecordFromStartup` setting; `Recorders.*`): what records over time is shared through `Recorders` (the History tab's `HistoryRecorder`, the RPC/ALPC tab's WinSys `IpcTracker`, the Disk tab's `FileIoTracker`, the Registry tab's `RegistryIoTracker`, the process creation tracker of the Processes tab's Tampered color and the Alerts' tampering rule, WinSys `ProcessCreationTracker`; each kept by a weak pointer: it starts when first acquired and stops when its last owner lets it go; the ETW sessions are named after the app's process, so there can be only one of each) and `NetworkTracking` (the per-process network tracker, shared with the property sheets' threads). Tabs acquire theirs when created (History) or first shown (RPC/ALPC, Disk, Registry), the network tracker while a byte column is shown. With the option on, the frame's `Recorders::Holder` acquires all five in `OnCreate` right after the first snapshot, before the views are created, so an open History tab gets the frame's recorder, and a tab opened later shows what happened since the app started (the RPC/ALPC and Disk status lines say since when; the Disk tab still forgets files idle for a minute). Turning it on starts them at once (without elevation only the History recorder starts, and a message says the rest need administrator rights); turning it off releases the frame's references, the open tabs keeping theirs. After every snapshot update, before the views' `OnRefresh`, `Recorders::OnRefresh` updates the history recorder and makes the trackers forget the processes that exited (the views no longer do it themselves). The cost: four ETW sessions (the registry's the busiest: about 3% of a core) and, while a service kind is on, a service enumeration per refresh, for as long as the app runs. Tested: with the option on and History closed, opening History later showed service and process events from before, its status line "since" the app's start; the RPC/ALPC tab, first shown later, said "since" the start too; turning it off at run time saved the setting; no WinSysLive ETW session was left after exit.
- **Leak Watch** (Options menu, `ID_OPTIONS_LEAKWATCH`, the `LeakWatch` setting, off by default; `LeakWatch.*`, `LeakWatcher.*`):
  - **Sampling:** while it's on, `CMainFrame::Refresh` hands each snapshot to the frame's `LeakWatcher`. Every 10 seconds (`LeakWatcher::Interval`, by the tick count, whatever the update interval) it samples every process but Idle and System: handles and private bytes from the snapshot, GDI and USER objects through `ProcessInfoEx` (GetGuiResources on the handle it keeps; unknown, so not kept, for the processes it can't open). Each process keeps the last half hour (`LeakSeries`, by `ProcessOrThreadKey`; the exited ones dropped at each sample) and is judged after each.
  - **The judgment** (`LeakDetector::Analyze`, tested in `Tests\LeakWatchTests.cpp`): at least 20 samples over 10 minutes. The growth from the first sample to the last must be at least 500 handles, 100 MB, or 300 GDI or USER objects, and a quarter of the first value. It must never fall back by more than a tenth of the growth (a garbage collector's sawtooth fails), both halves of the span must have grown by a quarter of it each (a step and a plateau, or a process that stopped growing, fail), and a straight line must fit (R squared at least 0.8).
  - **The findings** (`LeakFinding`: the counter, its first and last values, the span) are described as "handles 1,000 to 3,000 in 20 minutes". They're shown by the Processes tab's Leaks column (`CProcessesView::LeaksText`) and alerted by the ProcessLeaks rules, both through `IMainFrame::GetLeakWatcher`, which is null while Leak Watch is off.
  - **Turning it off or on** clears everything (`LeakWatcher::Clear`), so the 10 minutes start over.
- **Startup, updates and settings files** (Options and Help menus):
  - Run at Windows Startup writes the HKCU `Run` key's `WinSysLive` value, the exe's quoted path with `/minimized` (checked when the value names this exe, `IsRunAtStartup`, so the state is the registry's, not a setting). `Run` shows the window `SW_SHOWMINNOACTIVE` after the placement for `/minimized`, so with Minimize to Tray it goes to the tray. The Run key starts it unelevated. Run at Windows Startup (Elevated) is a logon task instead (WinSys `LogonTask`, "WinSysLive Startup (<user>)": the user's logon trigger, the highest run level, so no UAC prompt; the exe with `/minimized`), enabled only when elevated, as changing it needs that; it's checked when the task's action names this exe (`IsRunElevatedAtStartup`). Turning either on turns the other off, and while the task is on a non-elevated instance disables the plain entry (`UpdateStartupUI`), as both would start an instance (if it can read the task: otherwise it doesn't know).
  - Updates (`UpdateChecker.*`): the latest GitHub release (`api.github.com/repos/zodiacon/WinSysLive/releases/latest`, WinSys `Http::Get` on a detached thread, `tag_name` and `html_url` found by string searches) against the exe's ProductVersion without its fourth part, numerically (`CompareVersions`, a leading `v` ignored); the thread posts `WM_UPDATE_CHECKED` (an `UpdateInfo*` the frame deletes). Help > Check for Updates reports either way; Options > Check for Updates at Startup (`CheckForUpdates`, off by default) checks once a day at most (`LastUpdateCheck`, a FILETIME as text, set only after a successful check) and says something only when there's a newer version, failures silently. A WinGet install (the exe under a `WinGet\Packages` folder, the user's or the machine's, `IsWingetInstall`) is told the `winget upgrade` command line and offered the release page, as WinGet keeps its own record of the version; so is a release without a zip. Otherwise `CUpdateDlg` (`UpdateDlg.*`) offers Download and Install (and Release Page): `UpdateInstaller::PrepareAsync` (`UpdateInstaller.*`, a detached thread posting `WM_UPDATE_PROGRESS` and `WM_UPDATE_PREPARED`; closing the dialog cancels) downloads the release's `-x64.zip` asset to `%TEMP%\WinSysLive Update\<version>` (WinSys `Http::Download`), extracts it (`ZipArchive::Extract`) and verifies it: only the release's files are taken (WinSysLive.exe, dbghelp.dll, symsrv.dll, LICENSE.txt), the exe validly signed (WinSys `FileSignature`) by the running exe's signer when that's signed, its FileVersion the release's and not older than the installed one, the DLLs validly signed. Install and Restart then puts them beside the exe (`Install`): each file in the way renamed to `<name>.update.old` (a running exe and loaded DLLs can be renamed, not overwritten), the new one copied in (taking the folder's ACL), everything put back if one fails; then the settings are saved and the exe started again with `/restart`. When the folder isn't writable and the app isn't elevated, the button has the shield and `Install` runs the exe elevated with `/applyupdate "<files>" "<folder>"`, which `_tWinMain` hands to `UpdateInstaller::RunCommandLine` before anything else (exit code: 0 or the Win32 error); that half verifies again while holding the files open without write or delete sharing, as any of the user's processes could change a folder in TEMP, and marks the old files for deletion at boot. Each start deletes the `.update.old` files (retrying for a minute while the previous instance exits) and the downloads (`CleanupAsync`). Debug builds take `WINSYSLIVE_TEST_VERSION` as their version, to test against a release that isn't newer.
  - Export Settings saves the views' and the frame's settings (`SaveAllSettings`, as at logoff) and writes them all to an INI file (`SettingsTransfer::Export`: the file created as UTF-16 first, so `WritePrivateProfileString` keeps non-ASCII text; WTLHelper `Settings::SaveToFile`). Import Settings doesn't load into the running app (the views save their state over it as they close, and `LoadFromFile` would make the file where `Save` writes): it copies the file to `%LOCALAPPDATA%\ScorpioSoftware\WinSysLive\PendingImport.ini` and offers a restart (`/restart`, past Single Instance); `_tWinMain` applies a staged import right after loading the settings (`ApplyPendingImport`): the current settings exported to a temporary file, the imported `[General]` values written over them (so settings an older file lacks keep their values), that loaded and saved back to the registry key (`Settings::GetPath`), and both files deleted. The VirusTotal key is DPAPI-encrypted for the user, so it doesn't carry to another account.
- **Command line** (`CommandLine.*`, `CommandLineRun.cpp`): `WinSysLive /snapshot <file.wslsnap>` saves a snapshot as File > Snapshots does (`Snapshot::Capture`, `Save`: 575 processes with 34,468 modules, 337 services, 294 drivers and 655 autoruns in about 2 s here); `/compare <before> [<after>]` lists what changed (`SnapshotCompare::Compare`; without the second file, against the system now); `/export processes|modules|services|drivers|autoruns [/from <file>]` writes a table of the system now or of a saved snapshot (`CommandLine::ExportTable`: processes with their PIDs, path, command line, user, creation time as ISO 8601 UTC, counts; a row per module of each process; services; drivers; autoruns); `/export threads` every process's threads now (`LiveExportKinds`: snapshots don't keep threads, so `/from` is a mistake; `CaptureThreads` reads a process snapshot's `SYSTEM_EXTENDED_THREAD_INFORMATION` entries as the Threads tab does; `CommandLine::ThreadsTable`: PID, process, TID, state, wait reason for a waiting thread, priorities, CPU, kernel and user time, context switches, start address, creation time, none for the System threads created at boot, whose time is near 0; the states' and wait reasons' names from `ThreadText.cpp`, apart from `ThreadCommands.cpp` so the tests take them; 7,709 threads here; not elevated, a warning says there are no start addresses); `/help` or `/?` the usage. `/compare` and `/export` take `/out <file>`: CSV for a .csv file, else tab-separated text (`ListExport::ToCsv`/`ToText`, saved by `ListExport::Save`, UTF-8 with a BOM); without it the table goes to the console. `_tWinMain` handles them right after enabling SeDebugPrivilege and before the settings load (`CommandLine::Parse(GetCommandLine())`: a first argument of /snapshot, /compare, /export, /help or /?, - for / in any case; anything else, the window's own /minimized, /locks, /restart, starts the window): no window, no settings, no running instance asked. A GUI program has no console of its own: `Output` writes to a redirected standard handle (a file or a pipe, UTF-8) or attaches to the parent's console (`AttachConsole(ATTACH_PARENT_PROCESS)`, `CONOUT$`, `WriteConsole`). cmd.exe doesn't wait for a GUI program (`start /wait` does); PowerShell waits when the output is piped or redirected; the usage says so. Exit codes: 0 success, 1 a mistake in the arguments (the error, then the usage), 2 a failure (a file that can't be read or written). Not elevated, a warning says other users' processes have no modules or command lines. Parsing and the tables are in `CommandLine.cpp`, which the tests take (`Tests/CommandLineTests.cpp`, with `ListExport.cpp`); running them, which captures through the app's process snapshot, is `CommandLineRun.cpp`.
- **Symbols** (`Symbols.*`, `SymbolEngine`): DbgHelp, which isn't thread-safe, is called (through WinSys `SymbolHandler` and `MiniDump`) only on the engine's own thread; `Lookup` and `CaptureStack` may be called from any thread (the UI's, the property sheets') and answer with `WM_SYMBOLS_RESOLVED` (the window repaints; the next `Lookup` finds the cached text) and `WM_STACK_CAPTURED` (lParam: a `StackCapture*` the window owns). The engine loads the exe folder's `dbghelp.dll` before the first call (then `SymbolHandler::SetOptions`) (delay-loaded, so the copy beside `symsrv.dll` is the one used; the system's can't download). The search path comes from Options > Symbol Settings... (`CSymbolSettingsDlg`, `SymbolSettingsDlg.*`, after TotalPE's: the `Symbol*` settings as `SymbolPathOptions`), built by `BuildSymbolSearchPath` on the UI thread (the settings belong to it) and handed to the engine with `SetSearchPath` at startup and after the dialog: the extra paths, then `_NT_SYMBOL_PATH` (with `cache*` the cache added if it has a server but no cache), then `srv*`(cache)`*`(server) unless `_NT_SYMBOL_PATH` has a server; an empty cache is TotalPE's (its `SymbolCache` setting, else `%LOCALAPPDATA%\TotalPE\Symbols`). A new path closes the engine's sessions and clears its cache, so addresses resolve again with it. A process's session is a `SymbolHandler::ForProcess` (up to 16, the least recently used closed); kernel addresses use one `SymbolHandler::ForKernel`, whose module bases only an elevated process gets (tried once per search path). Resolved text is cached by process (ID and creation time) and address. A stack is captured by `SymbolHandler::CaptureStack` (the thread suspended only to copy its context and stack; the walk reads that copy, so no symbol download happens with a thread suspended), then resolved by the engine. WinSysLive's own threads are never suspended. Options > Resolve Symbols (the `ResolveSymbols` setting, on by default) turns `Lookup` off (the addresses show) and leaves stack frames without symbols. The Threads pages (lower pane and sheet) show the start address's symbol in Start Address, with the address in a tooltip (a tooltip for the whole list, popped when the mouse moves to another cell, as the list view's infotips are only for the first column), and open `CStackDlg` (`StackDlg.*`) from a row's context menu or a double-click: modal, filled when the capture arrives, with Refresh and Copy. Each frame shows its module and where its symbols came from (WinSys `SymbolHandler::GetModuleSymbols`, after resolving: the PDB's path, exports only, none, or not loaded while Resolve Symbols is off), the status line names the modules without a PDB, and double-clicking a frame opens its module's folder with the file selected. The row's context menu also has Set Priority (the seven levels, the current one checked from the page's handle; `ID_THREAD_PRIORITY_*`, in the menu's order) and Affinity... (`CAffinityDlg` with the thread's group, its label speaking of the thread; with several groups, every group is offered, a thread's processors in one of them, as choosing in another clears the rest, and another group moves the thread there, `Thread::SetGroupAffinity`, unless its process is held to its group by a mask), without confirmation, through `CThreadsPage::OpenRowThread`, and Suspend or Resume (by the snapshot: Waiting with a Suspended or WrSuspended wait reason) and Terminate, each after a confirmation, on a WinSys `Thread` opened with only the access it needs and checked against the row's creation time (`GetCreateTime`; a reused thread ID); they're grayed for the app's own threads (suspending one could hang it) and the Idle and System processes'. The new state shows with the next refresh. The menu's icons (`IDI_STACK`, `IDI_PAUSE`, `IDI_RUN`, `IDI_DELETE`) are set with `WTLHelper::InitMenu`, as the frame's are; it's thread-safe, so the sheets' pages use it too.
- **DPI** (per-monitor v2, from `WinSysLive.manifest`: the project's own DPI setting gives only v1, whose child windows get no `WM_DPICHANGED_AFTERPARENT`; `_WTL_DPI_SUPPORT` in `pch.h` for `CDialogResize`). Sizes are written at 96 DPI and scaled to the window's (`DpiHelper` from WTLHelper):
  - **Columns:** `ColumnManager::AddColumn` scales its width, so `ColumnLayout` and the views pass and save widths at 96 DPI (`GetShownColumns` scales them back); (The app's manifest, `WinSysLive.manifest`, declares Windows 10 and 11 support (`supportedOS` `{8e0f7a12-...}`): without it the version APIs lie, and `GetFileVersionInfo` gave kernel32.dll 6.2, Windows 8's version, in the Image views' Version; the unmanifested test program still sees 6.2.) A column added to a table later reaches saved layouts once: `ColumnDef::Added` is the table's version that added it (0 for the first columns), `Format` writes the table's version (its highest `Added`) as a last `~:N` entry when it's above 0 (an unknown key, skipped by older builds), and `Parse` adds the default columns newer than the text's version (none: 0) after the nearest column before them in the table that's shown, so hiding one afterwards sticks (`ColumnLayoutText.cpp`, apart from the dialogs so the tests take it; the Events tab's Details is version 1). The TreeListViews (Processes, Users, Memory) scale their own and get `ListViewHelper::EnableColumnDpiScaling` on the inner list, as do lists with columns inserted directly. That subclass, the filter box's and the pages' all rely on `WM_DPICHANGED_AFTERPARENT`, which WTLHelper's dark mode subclasses used to swallow (see `wtlhelper/CLAUDE.md`).
  - **Frame:** `WM_DPICHANGED` takes the suggested rectangle, rebuilds the shared image list in place (`UpdateImageList`: `SetIconSize`, the same handle and indices, process icons extracted again with `SHDefExtractIcon` at the new size), the toolbar's images and band (`UpdateToolBar`), the menu icons (`WTLHelper::InitMenu` takes an icon size; context menus pass `DpiHelper::SmallIconSize`), the status bar panes and a user font (`ApplyFont`), then calls `IView::OnDpiChanged` on every view, which gives its lists the image list again so their rows take its height. The window's placement is saved with its DPI (`MainWindowPlacementDpi`) and `Run` restores the size for the monitor's DPI.
  - **Filter box:** its width is at 96 DPI; it follows its DPI by itself (own font unless the view gave one, size, rebar band, or the parent's layout through a `WM_SIZE`).
  - **Dialogs** (`DpiLayout.h`): the property pages are child dialogs, which get `WM_DPICHANGED_AFTERPARENT` and which the dialog manager would relayout by the new font's dialog units, not the DPI ratio WTL's layouts scale by (rows came apart). So it only scales their fonts (`DDC_DISABLE_CONTROL_RELAYOUT`), and `CDpiDynamicDialogLayout` (for `CDynamicDialogLayout` pages) or `CDpiDialogResizePage` (`CDialogResize`) moves every control by the ratio and lays the page out again. Top-level dialogs with `CDialogResize` chain `CDpiDialogResize`: WTL's handler doesn't take the suggested size. A page or dialog calls `InitDpi` after `DlgResize_Init` (the dynamic layout's `InitDynamicLayout` does it itself).
  - The Threads page and the Wait Chain dialog have image lists of their own in the window's small icon size (the page rebuilds its on a DPI change); the tray icon stays at the system DPI.
