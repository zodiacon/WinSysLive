# Dialogs and menus

The dialogs (mostly the System menu's) and the menus that aren't a tab's, in detail. Read the entry before changing one.

- **Run and Run As** (File menu, `RunDlg.*`): Run (Ctrl+R) starts a command line as the shell does (WinSys `Process::Run`: ShellExecuteEx, so a document, folder or URL too; the first token is the file, quoted if it has spaces), elevated with the `runas` verb when asked (a declined prompt says nothing). Run as Limited User is the same dialog (`CRunDlg(true)`, no elevation check box): a program started without administrator rights (WinSys `Process::RunLimited`). Run As starts a program as another user (WinSys `Process::RunAs`: CreateProcessWithLogonW; `DOMAIN\user`, `user@domain` or a local name; the user's profile loaded, or the credentials for network access only, as `runas /netonly`). Both keep the last 20 command lines in `RunHistory` (newest first, one a line); Run As keeps the user name in `RunAsUser`, never the password, which is wiped once used. A failure is reported and keeps the dialog open.
- **Find Handle or DLL** (`FindHandleDlg.*`, Process menu, Ctrl+Shift+F): a modeless dialog the frame owns (`m_FindDlg`, created again once closed; `PreTranslateMessage` gives it `IsDialogMessage` first). The search runs on a `std::jthread` (stopped and joined by Stop, a new search or closing): processes from WinSys `Process::EnumProcessNames`, modules from `Process::EnumLoadedModules`, handles with `HandleEnumerator::EnumProcessHandles` and `HandleNames::QueryName`, matching case-insensitively; results go to a shared, locked state the dialog takes when the worker posts `WM_FIND_PROGRESS` (lParam: the search's ID, so a stopped search's messages are ignored), at most 10,000. A process whose file name query hangs has the rest of its files skipped (past 32 hung queries, all files are). Results have the frame's icons in their leftmost column: the modules icon for DLLs, `GetHandleIcon` for handles (`HandleIcons.*`, the Handles page's). Double-click or Go to Process calls `IMainFrame::GoToProcess`. A handle result keeps its `HandleEntry`, so Properties (the button, or the result's context menu) opens `CHandleSheet` on it, with a `PROCESS_DUP_HANDLE` handle opened for the dialog.
- **Snapshots** (`Snapshot.*`, `SnapshotDlg.*`, File > Snapshots..., Ctrl+Shift+N; `IDI_SNAPSHOT`, `Snapshot.ico`, on the menu item and the title bar): `Snapshot::Capture` records the system (its own `ProcessManager`, as the frame's belongs to the UI thread: each process's image, command line, user, counts and the modules it has loaded, `Process::EnumLoadedModules`, the image itself left out; the Win32 services with their configuration; the loaded kernel modules; WinSys `Autoruns::Enum`, so COM on the capturing thread), about 3 s and 2 MB here; handles are left out (each process keeps its count). The file (`.wslsnap`) is UTF-8 text, a record a line, tab separated, its first field the kind (P, M for a module of the P above it, S, D, A), after a header (`WinSysLive Snapshot`, the format's version; a newer one is refused, unknown kinds skipped) and the computer, OS and time; tabs, line breaks and backslashes escaped. `SnapshotCompare::Compare` matches what has no identity across time by what it is: processes by image path (instances counted: PIDs change), modules by path (with the processes loading them), services by name (state, start type, account, path, display name), drivers by path, autoruns by category, location and name (command, enabled); `Contents` lists one snapshot. `CSnapshotDlg` (modal, resizable): Before is a file or none, After a file or the system now (the default; captured again on every Compare); two files compare as soon as both are open; no Before lists After's contents. Save Snapshot captures to a file and makes it Before, for a later Compare against the system. Captures run on a detached thread that shares only a `CaptureState` with the dialog (`WM_SNAPSHOT_CAPTURED`; the buttons disabled meanwhile), so closing doesn't wait. Rows are green (added), red (removed) or amber (changed), sorted by kind and change until a header is clicked; the filter matches every column; Copy copies the selected rows or all shown; Open File Location (also a double-click) shows a row's file.
- **System Information** (`SystemInfoDlg.*`, System > System Information..., the menu's first item, `IDI_SYSINFO`, `sysinfo.ico`, on the item and the title bar): `CSystemInfoDlg`, modal and resizable, read-only, no elevation needed: a tab per area over one list that shows the selected tab's rows (refilled on `TCN_SELCHANGE`; the list is raised above the tab control, which has `WS_CLIPSIBLINGS`, as the tab control painted over it otherwise), some grouped under titles drawn bold and shaded (as Page Files'), from WinSys `SystemDetails`: Operating System (product with the display version, edition, version with the UBR, build lab, installation type, architecture, the last feature update's install time, last boot (fast startup said) and uptime, computer and NetBIOS names, domain or workgroup, registered owner, locales), Computer (SMBIOS system, baseboard and BIOS, the firmware type), Processor (CPUID vendor, family, model and stepping, microcode, base speed, cores with the P/E split of a hybrid processor, logical processors, groups and NUMA nodes when more than one, caches, the hypervisor; virtualization and SLAT only without a hypervisor, as Windows then reports no SLAT; the features), Memory (installed, usable, slots used, then each populated slot's module under Modules) and Security (grouped: Boot, Virtualization-Based Security, Code Integrity, Credentials, Kernel, Speculative Execution, User Account Control; Secure Boot, VBS, memory integrity, the code integrity options, App Control, Smart App Control, Credential Guard (LsaIso running), LSA protection (the `RunAsPPL` value), the kernel debugger, kernel CET, Kernel DMA Protection, System Guard, KVA shadow and the speculation mitigations, MDS and BHI "Not affected" on AMD, which Windows reports nothing for, and UAC). Rows without a value are left out, and groups without rows. Refresh reads every tab again, keeping the tab and the selected row by name; Copy copies the selected row, or the tab's rows with `[Group]` titles, tab separated.
- **Firmware and TPM** (`FirmwareDlg.*`, System > Firmware and TPM...; the System menu (the Tools menu before, so its first command is still `ID_TOOLS_FIRMWARE`) is for dialogs that aren't tabs): `CFirmwareDlg`, modal and resizable (`CDpiDialogResize`), read-only, with a tab control over two panes shown and hidden by hand. Summary: the firmware type, Secure Boot and Setup Mode, the boot timeout, current and next entries and the boot entries in boot order (WinSys `Firmware`), and the TPM (WinSys `Tpm`), in sections drawn bold and shaded (custom draw). UEFI Variables: every variable (name, vendor GUID with a few known vendors named, attributes as NV/BS/RT..., size), sorted by name, the selected one's value as a hex dump in a read-only Consolas edit below. The variables need SeSystemEnvironmentPrivilege, so elevation; otherwise the summary and the status line say so. Refresh reads all again; Copy copies the summary (`[Section]` titles, tab-separated rows) or the selected variable with its dump. The tab control has `WS_CLIPSIBLINGS` and the panes are raised above it (`HWND_TOP`), as in the other tabbed dialogs: otherwise it can paint over them when the selection changes.
- **Computer menu** (after System, `CMainFrame::OnComputerCommand`, WinSys `Power`): Lock, Log Off, Sleep, Hibernate, Restart, Shut Down, Restart to Boot Options (Windows' advanced startup) and Restart to Firmware (the UEFI setup, as `shutdown /r /fw`). The ones that close programs (log off, the restarts, shut down) ask first, the button defaulting to Cancel; the settings are saved by `WM_ENDSESSION` as at any logoff. Sleep is enabled when the system has S1-S3 (not Modern Standby's S0, which `SetSuspendState` doesn't enter), Hibernate when it has S4 and a hibernation file, Restart to Firmware when elevated on UEFI firmware that offers booting to its setup; set once, at startup. A failure is reported.
- **Tools menu** (after Computer): Install Driver/Service... (`ID_TOOLS_INSTALLSERVICE`, `CMainFrame::OnInstallService`) runs the Services tab's `CServiceInstallDlg` (WinSys `ServiceManager::Install`) with its own title, a service by default (the type combo box chooses a driver); the status line names what was created, and the Services and Drivers tabs show it with their next refresh.
- **Memory lists** (System > Memory Lists, `CMainFrame::OnMemoryListCommand`): Empty Working Sets, Flush Modified List, Purge Standby List and Purge Low-Priority Standby List (WinSys `MemoryLists::Execute`), as RAMMap's Empty menu, each after a confirmation that says what it does; enabled only when elevated (SeProfileSingleProcessPrivilege); afterwards the status line has the free, standby and modified sizes before and after. The Performance tab's Memory page shows the lists in detail beside its graph when it's wide enough (`CPerfMemoryPage::m_Lists`, a plain report list whose rows are `ListRow`, texts set in place on every sample: zeroed, free, modified with its page-file and no-write parts, standby with each priority from 7 down, as RAMMap, and the pages repurposed from each since boot, and bad), from `PerfSample::Lists` (`MemoryLists::Read`, elevated only, as before; the composition bar is unchanged).
- **Pipes and Mailslots** (`PipesDlg.*`, System > Pipes and Mailslots..., `IDI_PIPE`, `pipe.ico`, on the menu item and the dialog's title bar): `CPipesDlg`, modal and resizable, read-only, no elevation needed: every named pipe and mailslot (WinSys `Pipes::EnumPipes`/`EnumMailslots`) in one list (kind, with `IDI_PIPE` or `IDI_MAILSLOT`, `mailbox.ico`, from an image list of the dialog's own in its small icon size; name, a pipe's current and maximum instances, creation time: only mailslots have one, as the named pipe file system reports no times), by name until a header is clicked (any column; ties by name), with a filter box above it (the name and the kind, as typed). Nothing is opened, as opening a pipe would connect to it. Copy copies the selected rows, or every row shown. The mailslots are appended to the pipes one by one: a range `insert` of the WinSys type warned C4530 under LTCG (see `winsys/CLAUDE.md` on exceptions).
- **Network Information** (`NetworkInfoDlg.*`, System > Network Information..., `IDI_NETWORK`): `CNetworkInfoDlg`, modal and resizable, a tab per table over one list (the list and the filter raised above the tab control, which has `WS_CLIPSIBLINGS`): Listening Ports (WinSys `ConnectionInfo::Read`'s listening TCP sockets and every UDP endpoint, with the process's name from the frame's snapshot; double-click goes to the process, closing the dialog), DNS Cache (WinSys `NetworkTables::ReadDnsCache`, from WMI; Flush DNS Cache, shown on that tab, after a confirmation), Neighbors (ARP) and Routes (with the interface metric). All read when it opens and on Refresh; the columns are set again on a tab change; any column sorts (numeric ones as numbers) and the filter matches any; Copy copies the selected rows, or all shown, with the column names. The list's context menu (`WM_CONTEXTMENU`, also from the keyboard) has Go to Process (listening ports; `ID_NETINFO_GOTOPROCESS`, as the double-click), Flush DNS Cache (the DNS tab) and Copy (Copy All without a selection). Listening sockets can't be closed (the IP helper resets only connections with a remote end), so there's no Close Connection.
- **Power Requests** (`PowerRequestsDlg.*`, System > Power Requests..., `IDI_CAPABILITY`, `Power.ico`): `CPowerRequestsDlg`, modal and resizable, read every 2 seconds (`SetTimer`; the selected rows kept by their first two cells): the system timer resolution on top (WinSys `PowerRequests::GetTimerResolution`: current, finest and coarsest; a current finer than the coarsest is said to cost power), the power requests (`PowerRequests::Enum`: what each holds, Display, System, Away mode, Execution, Performance boost and Active lock screen with counts above 1; requester: a process's image file name, a service's name with its host, or a driver's device description; kind, PID, reason, the path or device instance path; Show Inactive adds the requests created but not set) above the wake timers (`EnumWakeTimers`: expiry as local time, period, requester, reason). Both lists sort by any column (the PID by number, the expiry by time). Double-click or Go to Process (the context menu) goes to a process's or service host's process, closing the dialog; Copy copies the list that last had the focus. The data needs elevation, as for powercfg; the status line says so otherwise. Checked against `powercfg /requests` and `/waketimers`: the same entries, reasons and service names.
- **Alerts** (`Alerts.*`, `AlertRules.*` (the kinds, `AlertRule`'s description, text format and pattern matching, and `AlertCondition`, without the app around them: the tests take them), `AlertsDlg.*`, Options > Alerts..., also in the tray icons' menu): `CAlerts`, owned by the frame, evaluates the rules after every snapshot update (`CMainFrame::Refresh`, after the tray icons; paused updates evaluate nothing): a process starts or exits (`GetNewProcesses`/`GetTerminatedProcesses`), the system's CPU (the Idle process's, as the status bar's), commit charge or physical memory in use (`SystemInfo::GetPerformanceInformation`, read only when such a rule is on) above a percentage, or a process's CPU (percent of the whole system) or private bytes (MB) above a threshold, or an event is logged (System, Application or Security, or any of them; by source, a `PathMatchSpec` pattern, and event ID; one of the two at least, as the rule dialog insists) or a Security audit failure is logged (optionally by source and ID): `CAlerts` is an `EventLogSink` with an `EventLogWatcher` of its own whose per-log queries come from the enabled event rules (`AlertRule::EventQuery`: an exact source name as `Provider[@Name=...]` quoted with the other quote, the ID, the audit failure keyword, ORed; a wildcard source left to the matching after arrival; `*` when a rule narrows nothing), restarted with the rules; its callbacks queue the events (at most 1,000, as updates may be paused) and each update matches them (`AlertRule::MatchesEvent`), an event firing its first matching rule, as "<log> event <ID> from <source>: <text>" or "Security audit failure <ID> (<source>): <text>" (the source left out when it's Microsoft-Windows-Security-Auditing, the Security log's own), with the logging process (Go to Process while it runs and started before the event); the event kinds' rules have two more fields in the setting (`|Log|EventId`), lines older builds skip. The text is the message's first line, which says little for the Security log ("An account failed to log on."), so for the Security log's events and any event without a message the data fields are used too (read with each event by the watcher, `EventLogWatcher::Start`'s data, rather than found again by record ID, which costs 13 ms an event in a large Security log) and `EventAlertText::Summarize` (`AlertRules.*`, tested) words them: the well-known Security events by their fields (4624 and 4625 logons with the account, the address or workstation, the logon type in words and a failure's reason from its sub-status, else status: wrong password, no such user, locked out...; 4648 explicit credentials; 4688 "<image> created by <account>, parent <image>"; account and group changes 4720-4757; 4740 lockouts; 4771 Kerberos pre-authentication and 4776 NTLM validation failures; 4656/4663 object access; 4697/7045 service installs; 1102 the log cleared), other Security events the line with up to three main fields in parentheses (user, by, from, process, object, service), an event without a message its first fields; the log's placeholders ("-", the null SID, unresolved "%%NNNN") count as empty. Tested live with event 4688 from Microsoft-Windows-Security-Auditing (a process created, as this machine audits process creation): "Security event 4688: C:\Program Files\Git\cmd\git.exe created by ZODIAC\zodia, parent ...". The Events tab's Alert on Events Like This... opens the rule dialog filled in (`IMainFrame::AddAlertRule`, which adds the rule on OK). A rule's alerts of one update go through its `AlertThrottle` (`AlertRules.*`, tested; per rule in `RuleState`, reset by `SetRules`): more than 3 at once become one, "<the first> (and 24 more like it)"; a rule's quiet period (the rule dialog's Quiet period, in seconds; `AlertRule::Quiet`, an eighth field `|Log|EventId|Quiet` in the setting written only when set, with empty event fields for the other kinds, so rules without one stay readable by older builds; `Describe` adds ", at most once a minute") allows at most one alert an update and none until it ends, the next one counting those held back, "(5 more during the quiet period)" (those held back with nothing firing after the period aren't reported). A rule on 4688 made 25 alerts in two seconds before this. Or a service starts, stops or fails (stops with an error: the Win32 exit code, or the service's own after `ERROR_SERVICE_SPECIFIC_ERROR`; `ERROR_SERVICE_NEVER_STARTED` isn't a failure). Services are enumerated (`ServiceManager::EnumServices`, all of them, drivers too) only while a service rule is on, compared by name with the last read (`UpdateServices`: pending states waited out, as the History tab does; the first read, and the first after the rules turn one on, is a baseline); service rules match the service's name or display name, and the rule dialog's field and hint say Services for them. Tested by starting and stopping msiserver (Windows Installer, demand-start, left stopped as it was): a start by name with its PID, a stop by display name, no failure. Process rules match image names with `PathMatchSpec` (wildcards, `;`-separated patterns; empty: any). A threshold rule fires when the value has stayed above it for its seconds (`Condition`: since when, fired), then not again until it drops back under; process conditions are per process (by ID and creation time) and dropped with the process. Nothing fires on the first update (the baseline). Each refresh's new alerts make one balloon (`CAlertIcon`, the app's icon in the notification area, ID 100, shown while any rule is enabled so balloons don't depend on the graph icons; `NIIF_WARNING`; the first alerts that fit in 200 characters, then how many more); clicking it (`NIN_BALLOONUSERCLICK`) restores the window and goes to the last alert's process if it still runs; the icon's clicks and menu are the tray icons'; Explorer restarting adds it again. Each rule's matches since the app started and the alerts they became are counted (`CAlerts::GetCount`, `AlertCount`; kept by the rule's text with Enabled ignored, `CountKey`, so they survive `SetRules` for a rule that stays the same and a rule turned off and on), shown in the rules list's Fired column ("30 times (1 alert)" when grouping or the quiet period held some back), to tell which rules are noisy; the recent alerts' Alert column is 900 wide, as the text carries the summary. The last 500 alerts are kept (`GetRecent`, not saved). `CAlertsDlg`: the rules with check boxes (enable), Add... (`CAlertRuleDlg`: kind, image names, threshold with its unit, seconds; the fields the kind doesn't use disabled; a percentage must be 0 to 100), Edit... (or a double-click), Remove, each saved at once (the `AlertRules` setting: a rule a line, `Kind|Enabled|Threshold|Seconds|Pattern`, the kind's key fixed) and applied (`SetRules` restarts every condition); the recent alerts, newest first, with Clear; double-clicking a running process's alert goes to it. `IDI_ALERT` (`Alert.ico`) on the dialog and the menu item; the notification icon stays the app's, so it reads as WinSysLive's.
- **ETW Sessions** (`EtwSessionsDlg.*`, System > ETW Sessions..., `IDI_ETW`): `CEtwSessionsDlg`, modal and resizable: the running sessions (WinSys `EtwSessions::Enum`: name, logger ID, mode, providers, buffers, events lost, buffers written, log file) above the selected one's providers (name, or the GUID when TDH doesn't know it; level, keywords, the processes whose instances it enabled, named from the frame's snapshot); the providers keep their height (not a resize group, as in the Logon Sessions dialog). The filter keeps the sessions whose name or one of whose providers matches (name or GUID), and their matching providers (all when the session's name matched), so typing a provider shows who traces it (the app's own trackers' sessions included). Both lists sort by any column (numbers as numbers); filling the sessions list doesn't refill the providers on every selection change (`m_FillingSessions`), as a session may have over a thousand; Refresh keeps the session by name; Copy copies the list that last had the focus. Stop Session... (the button, or the session list's context menu; WinSys `EtwSessions::Stop`) stops the selected session after a confirmation worded by whose it is: an orphan, a running WinSysLive's (what it shows stops updating), or Windows' or another program's (a warning: event logs, diagnostics or that program's tracing stop until it starts the session again). A session is orphaned ("(orphaned)" after its name) when its name starts with "WinSysLive " and the process named by the number at its end (before a `.`: the .NET page's sessions are `<pid>.<n>`) is gone, has exited, or has an image not named WinSysLive*; another user's running process (access denied) isn't. Stop Orphaned (N), enabled only when there are some, stops them all after one confirmation listing them. The last stop's outcome leads the status line until Refresh. Tested with a session made by `logman start "WinSysLive Test 99999" -rt -ets`.
- **Command palette** (`CommandPaletteDlg.*`, View > Command Palette..., Ctrl+Q): `CMainFrame::OnCommandPalette` walks the main menu (`GetMenu`, recursively) into commands with their menu paths and shortcuts (the text after the tab), leaving out separators, the palette itself and the commands the update UI or the menu has disabled (`UIGetState`), marking checked ones and giving the tabs their icons (`s_Tabs`); `CCommandPaletteDlg` is a borderless popup near the frame's top: a filter box (every word typed must be in the name or the path; names starting with the text first) over a list without a header; Up, Down, Page Up and Page Down move in the list while typing (the box subclassed, `ALT_MSG_MAP(1)`), Enter or a double-click runs the command (posted to the frame, which routes a view's commands to the active view), Escape or deactivation closes it. The check mark is `\x2713` in the source: the sources are compiled as ANSI, so a literal one came out garbled. A screenshot by `PrintWindow` showed its list unpainted while the screen had it right; it redraws itself once shown anyway (`WM_SHOWN`). With nothing typed, the commands last run from it come first (the `CommandPaletteRecent` setting: up to 8 IDs, newest first, comma separated; updated by the frame after each run). It also searches (`SetSearch`): from two characters typed, matching items come below the commands, a word each in the name, kind or detail, names starting with the text first, at most 25 of a kind (`MaxPerKind`: "svc" would otherwise be all svchost.exe) and 100 in all; the processes from the frame's snapshot at once (image name, "PID n", the process icon; Go to Process), and from a loader the palette runs on a `std::jthread` of its own the services (display name, service name; `CMainFrame::GoToService`, which selects it in the Services tab through `IView::ShowService`, clearing a filter that hides it), the loaded drivers (kernel modules: name, path; Go to Kernel Module) and the present devices (name, class; `CMainFrame::ShowDevice`, the device's Resources and Drivers dialog, as the Devices tab's scan may not be done), with the tabs' icons, looked up by the frame beforehand as the loader's thread touches no frame state; the loader's items are kept under a lock and announced by a `WM_SEARCHLOADED` with no payload (merged, the list shown again; "Searching services, drivers and devices..." until then, not selectable), so nothing leaks when the palette closes first, and the destructor joins the thread. A result's item data is -1 minus its index (a command's is its index); choosing one ends the dialog with its action (`GetSearchAction`, a `std::function`), which the frame runs after it closed. Tested: "spool" found spoolsv.exe and the Print Spooler service, and choosing the service selected Spooler in the Services tab. The open tabs add their own rows (`IView::GetSearchEntries`, `SearchEntry` in `Interfaces.h`: name, kind, detail, key, image), gathered on the UI thread before the palette opens; choosing one activates its tab and calls `IView::ShowSearchEntry` with the key, which selects the row, clearing a filter that hides it ("It isn't there anymore" otherwise): the Events tab gives every event it read (its Details summary, else the message's line; "System 7031, Service Control Manager"; the level's icon, `LevelImage`), so "conhost created" finds those 4688 events. The loader adds the connections (WinSys `ConnectionInfo::Read`: the remote end with its port, "[addr]:port" for IPv6, or a listener's local one; the detail starts with the process, from a PID-to-name map made from the snapshot beforehand, as the last column is narrow, then the protocol, state and local end; Go to Process); "443" lists the HTTPS connections.
- **Open PE File** (File > Open PE File..., `ID_FILE_OPENPE`; also files dropped on the window): `CPEFileDlg` (the Image page's views of any file on disk, see processes-view.md). The frame accepts dropped files (`DragAcceptFiles`, `WM_DROPFILES`: each file in turn, folders skipped); as the app runs elevated, `ChangeWindowMessageFilterEx` lets `WM_DROPFILES`, `WM_COPYDATA` and `WM_COPYGLOBALDATA` (0x49, which carries the file list) through from a non-elevated Explorer, which UIPI would otherwise drop. Tested with the file dialog on System.dll, kernel32.dll and WinSysLive.exe; a real drop wasn't simulated (the frame's `WS_EX_ACCEPTFILES` was checked).
- **Window Stations and Desktops** (`WindowStationsDlg.*`, System > Window Stations and Desktops..., `IDI_WINSTA`): `CWindowStationsDlg`, modal and resizable: a tree of sessions, window stations and desktops (WinSys `WindowStations::Enum`; the frame's `IDI_SESSION`, `IDI_WINSTA` and `IDI_DESKTOP`; another session's stations by name only; desktops with the input desktop and heap sizes said; this process's input desktop selected at first) beside the selected desktop's top-level windows in Z order (`WindowStations::EnumDesktopWindows`, only for the app's own station's desktops: the status line says why for others): #, handle, title, class, process (from the frame's snapshot), PID, TID, state, rectangle. Visible Only (on at first) and the filter (title, class, process, handle, PID) choose the rows; any column sorts; Refresh keeps the selected desktop; double-click or Go to Process goes to the window's process (closing the dialog); Bring to Front (`ProcessWindows::BringToFront`); Copy.
- **Network Shares** (`NetworkSharesDlg.*`, System > Network Shares..., `IDI_SHARE`, `share.ico`, on the menu item and the dialog's title bar): `CNetworkSharesDlg`, modal and resizable, read-only: the local shares (WinSys `NetworkShares::Enum`) by name in a list (name, path, type, uses, maximum, comment) and the selected one's details below in sections drawn bold and shaded (share; settings: offline caching, access-based enumeration, encryption...; share permissions, each trustee with Allow or Deny and Full Control, Change or Read; the system's special shares have none). When only level 1 was allowed, the status line says the paths, uses and permissions need elevation (current Windows gives them to a local caller anyway). Open (enabled for a disk share with a path) or a double-click opens its folder in Explorer; Refresh keeps the selection by name; Copy copies the list that last had the focus.
- **Page Files** (`PageFilesDlg.*`, System > Page Files...): `CPageFilesDlg`, modal and resizable, read-only, no elevation needed: the page files in use (WinSys `PageFiles::Enum`: size, in use with its share, peak, minimum and maximum) in a list that keeps its height, and below it, in sections drawn bold and shaded, the commit charge, limit and peak (`SystemInfo::GetPerformanceInformation`), physical memory and the page file space in use; the configuration (`PageFiles::GetConfiguration`: managed automatically, or each file's system-managed or initial and maximum sizes, the files created at boot, clearing at shutdown, whether the kernel and drivers are paged; the section's note says it applies at the next boot); and the swap file (`swapfile.sys` on the system drive, found by `FindFirstFile`, which needs no access to it). Refresh reads again; Copy copies the list that last had the focus.
- **RAM** (`RamDlg.*`, System > RAM..., `IDI_MEMORY` on the menu item and the title bar; enabled only when elevated): `CRamDlg`, modal and resizable, read-only, as RAMMap's Use Counts: physical memory by use (Process Private, Mapped File, Shareable, Page Table, Paged and Nonpaged Pool, System PTE, Session Private, Metafile, AWE, Driver Locked, Kernel Stack, Hyperspace (Windows 11's use 12, a process's hyperspace, worked out from the kernel's code: see `winsys/CLAUDE.md`); a use WinSys doesn't name as "Other (n)" when it has pages) and by list (Active, Standby, Modified, Modified No-Write, Transition, Zeroed, Free, Bad), from WinSys `PageUseCounts::Read`; zeroed, free and bad pages go under Unused, whose use means nothing, and Total stays last whichever way a header sorts. Sizes in K as RAMMap's (`FormatSize`), empty for none. The read takes seconds (about 6 s for 128 GB), so it runs on a `std::jthread` (`WM_RAM_SCANNED`) when the dialog opens and on Scan Again (disabled meanwhile); closing sets `m_Cancel`, which the read checks between batches, and joins. It was a tab first, dropped for the slow scan. Pages move between lists during a scan, so the totals aren't a snapshot and differ a little from the memory lists' counters. The list is multi-select (Copy copies the selected rows, else all, with the column names), so the selection is kept by row key through `GetNextItem`, not WTL's `GetSelectedIndex`, which asserts on such a list.
- **Logon Sessions** (`LogonSessionsDlg.*`, System > Logon Sessions..., `IDI_LOGON_SESSIONS`, `window_logon.ico`, on the menu item and the dialog's title bar): `CLogonSessionsDlg`, modal and resizable (`CDpiDialogResize`; the sessions list takes the extra size, the details below keep their height: a `DLGRESIZE` group of the two, one above the other, kept the list's first width, as WTL's groups lay out along one axis), read-only: every logon session from WinSys `LsaSecurity::EnumLogonSessions(true)` (`LsaEnumerateLogonSessions`) in a list (logon ID, user, logon type, session, package, logon time, logon server, SID), in the enumeration's order until a header is clicked (`SortItems` on the item data, the index in `m_Sessions`; the logon ID, session and time sort as numbers), and the selected one's details below (Identity, Logon, Profile, Account sections drawn bold and shaded, empty rows left out). Another user's session has only its logon ID unless elevated (`LogonSessionData::Error`): grayed, "(access denied)", its details and the status line saying elevation is needed. Refresh reads again, keeping the selection by logon ID; Copy copies the list that last had the focus (`NM_SETFOCUS`): every session with a header line, or the details as `[Section]` titles and tab-separated rows.
- **Window finder** (`WindowFinder.*`): the toolbar's target button (`ID_FIND_WINDOW`), dragged onto a window as in Process Explorer, not clicked. `CWindowFinder` subclasses the toolbar, so a press on that button captures the mouse instead of the toolbar's own handling; the window under the cursor (`CWindowFinder::WindowFromPoint`: the outermost ancestor of the same process, so a Store app's CoreWindow rather than its ApplicationFrameHost frame) is outlined by `CWindowHighlight` (a topmost layered, transparent popup with a frame-shaped region, which `WindowFromPoint` looks through) and named in the status line's first pane (process, PID, title by `InternalGetWindowText`, which sends no message, and class), whose text is restored afterwards; releasing calls `GoToProcess`. Escape (in `PreTranslateMessage`) or losing the capture cancels.
- **VirusTotal** (`VirusTotalChecker.*`, `VirusTotalDlg.*`): a VirusTotal column (hidden by default; detections over engines, "0/72", else the state: Queued, Checking..., Unknown, Analyzing..., an error) in the Processes view (the image), the Modules pages (images only, also on the sheets) and the Kernel Modules view, and a VirusTotal submenu in their row menus (the process one in `IDR_CONTEXT` and the Process menu): Open Report (the file's page on virustotal.com by its SHA-256, computed if not known; no API key needed), Check Again (`Recheck`) and Submit File... (after a confirmation that says VirusTotal shares uploads with its partners). `VirusTotalChecker` is one thread-safe object for the app (the sheets' pages use it on their threads), never destroyed, with one detached worker: `Query` returns what's known and queues a file the first time it's asked for, at the front (rows shown last come first: the columns ask only for the rows painted); the worker hashes it (WinSys `FileHash::Sha256`), reuses a report found for the same hash under another path, else looks the hash up (WinSys `VirusTotal::LookupHash`), paced at the `VirusTotalRate` setting's requests a minute (4, the free API's); results last the session. Only `Submit` uploads (WinSys `VirusTotal::UploadFile`), after which the hash is looked up every minute (up to 15 times) until analyzed. Windows that show the column register with `AddListener` and get `WM_VIRUSTOTAL` (they drain the queue of them and repaint once). Options > VirusTotal... (`CVirusTotalDlg`): the API key, in the `VirusTotalKey` setting DPAPI-encrypted for the user (`VirusTotalChecker::Protect`/`Unprotect`, hex), handed to the checker at startup and after the dialog (`SetApiKey`; without one the column says No API key and nothing is sent), and the rate. The menus' commands copy the path before any message box, as refreshes go on.
- **Wait chains** (`WaitChainDlg.*`): Wait Chain... in the Threads pages' row menu (one thread) and Analyze Wait Chain... in the Process menus (every thread of the process, from the snapshot) open `CWaitChainDlg`, modal, filled from a `std::jthread` (WinSys `WaitChainTraversal::GetThreadWaitChain` per thread, which can wait on hung processes) that posts `WM_WAITCHAINS_READ`. A chain's nodes are rows indented by depth (thread, the object it waits for, the thread owning that...); deadlocked chains (WCT's cycle) come first and are red, then the chains through other threads; a node WCT knows only by process (out-of-process COM, a process wait) shows the process. The wait time shows only for blocked threads. Refresh reads again; Copy copies the rows.
- **About box** (`AboutDlg.*`), as TotalPE's: the product name, version and copyright read from the exe's version resource (WTLHelper `VersionResourceHelper`), so only `VS_VERSION_INFO` needs changing for a release, and a SysLink to the GitHub repository (`ICC_LINK_CLASS` is in `AtlInitCommonControls`).
