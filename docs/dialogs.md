# Dialogs and menus

The dialogs (mostly the System menu's) and the menus that aren't a tab's, in detail. Read the entry before changing one.

- **Run and Run As** (File menu, `RunDlg.*`): Run (Ctrl+R) starts a command line as the shell does (WinSys `Process::Run`: ShellExecuteEx, so a document, folder or URL too; the first token is the file, quoted if it has spaces), elevated with the `runas` verb when asked (a declined prompt says nothing). Run as Limited User is the same dialog (`CRunDlg(true)`, no elevation check box): a program started without administrator rights (WinSys `Process::RunLimited`). Run As starts a program as another user (WinSys `Process::RunAs`: CreateProcessWithLogonW; `DOMAIN\user`, `user@domain` or a local name; the user's profile loaded, or the credentials for network access only, as `runas /netonly`). Both keep the last 20 command lines in `RunHistory` (newest first, one a line); Run As keeps the user name in `RunAsUser`, never the password, which is wiped once used. A failure is reported and keeps the dialog open.
- **Find Handle or DLL** (`FindHandleDlg.*`, Process menu, Ctrl+Shift+F): a modeless dialog the frame owns (`m_FindDlg`, created again once closed; `PreTranslateMessage` gives it `IsDialogMessage` first). The search runs on a `std::jthread` (stopped and joined by Stop, a new search or closing): processes from WinSys `Process::EnumProcessNames`, modules from `Process::EnumLoadedModules`, handles with `HandleEnumerator::EnumProcessHandles` and `HandleNames::QueryName`, matching case-insensitively; results go to a shared, locked state the dialog takes when the worker posts `WM_FIND_PROGRESS` (lParam: the search's ID, so a stopped search's messages are ignored), at most 10,000. A process whose file name query hangs has the rest of its files skipped (past 32 hung queries, all files are). Results have the frame's icons in their leftmost column: the modules icon for DLLs, `GetHandleIcon` for handles (`HandleIcons.*`, the Handles page's). Double-click or Go to Process calls `IMainFrame::GoToProcess`. A handle result keeps its `HandleEntry`, so Properties (the button, or the result's context menu) opens `CHandleSheet` on it, with a `PROCESS_DUP_HANDLE` handle opened for the dialog. Mapped Files (off by default: a `VirtualQueryEx` walk of every process) adds the data files mapped into the processes (WinSys `ProcessModuleTracker`'s views of type `Data`; the images are the DLLs), with the data-module icon. Whole Path matches a name that is the text's path, or under it for a folder (`LockPath::Matches`, `LockPath.h`, header-only and tested: case-insensitive, a trailing backslash ignored, a drive's root matching everything on it, `C:\Temp` not matching `C:\Temp2`), without the text lowercased. Close Handle (a handle result, not this process's) closes it in its process (`HandleNames::CloseInProcess`, checked against the type, after a confirmation) and Kill Process terminates the result's process (not this one, Idle or System), both opening the process by PID and creation time (every result now keeps it), so one that took the ID since isn't touched; the results they leave behind are removed (`RemoveResults`). **Who's locking a file**: `FindLocks(path)` checks Handles, DLLs, Mapped Files and Whole Path and searches, from `CMainFrame::ShowLocks`: Process > Who's Locking a File... (a file-open dialog), a folder dropped on the window (or a file with Shift; other files still open Image Details), and Explorer's menu: Options > Who's Locking in Explorer's Menu (`ExplorerMenu.*`) writes the current user's verb `WinSysLive.Locks` under `HKCU\Software\Classes\{*,Directory,Drive}\shell` ("Who's Locking This? (WinSysLive)", the exe's icon, `"exe" /locks "%1"`; checked when its command names this exe; on Windows 11 under Show More Options). The instance Explorer starts finds a running one (`ActivateRunningInstance`, Single Instance or not) and sends it the path (`WM_COPYDATA`, `ExplorerMenu::CopyDataLocks`, let through UIPI for an elevated instance), which posts itself `WM_SHOW_LOCKS` so the sender returns at once; with none running, or one that doesn't answer in 5 seconds, it opens the dialog itself after its window is up. `GetLocksArgument` (tested) takes the path after `/locks`, mending a drive's `"C:\"`, whose backslash escapes the closing quote.
- **Snapshots** (`Snapshot.*` (the file format and the comparison, which the tests take: a round trip with escaped tabs, line breaks and backslashes, a file that isn't a snapshot, Compare's added, removed and changed rows), `SnapshotCapture.cpp` (`Snapshot::Capture`), `SnapshotDlg.*`, File > Snapshots..., Ctrl+Shift+N; `IDI_SNAPSHOT`, `Snapshot.ico`, on the menu item and the title bar): `Snapshot::Capture` records the system (its own `ProcessManager`, as the frame's belongs to the UI thread: each process's image, command line, user, counts and the modules it has loaded, `Process::EnumLoadedModules`, the image itself left out; the Win32 services with their configuration; the loaded kernel modules; WinSys `Autoruns::Enum`, so COM on the capturing thread), about 3 s and 2 MB here; handles are left out (each process keeps its count). The file (`.wslsnap`) is UTF-8 text, a record a line, tab separated, its first field the kind (P, M for a module of the P above it, S, D, A), after a header (`WinSysLive Snapshot`, the format's version; a newer one is refused, unknown kinds skipped) and the computer, OS and time; tabs, line breaks and backslashes escaped. `SnapshotCompare::Compare` matches what has no identity across time by what it is: processes by image path (instances counted: PIDs change), modules by path (with the processes loading them), services by name (state, start type, account, path, display name), drivers by path, autoruns by category, location and name (command, enabled); `Contents` lists one snapshot. `CSnapshotDlg` (modal, resizable): Before is a file or none, After a file or the system now (the default; captured again on every Compare); two files compare as soon as both are open; no Before lists After's contents. Save Snapshot captures to a file and makes it Before, for a later Compare against the system. Captures run on a detached thread that shares only a `CaptureState` with the dialog (`WM_SNAPSHOT_CAPTURED`; the buttons disabled meanwhile), so closing doesn't wait. Rows are green (added), red (removed) or amber (changed), sorted by kind and change until a header is clicked; the filter matches every column; Copy copies the selected rows or all shown; Open File Location (also a double-click) shows a row's file.
- **System Information** (`SystemInfoDlg.*`, System > System Information..., the menu's first item, `IDI_SYSINFO`, `sysinfo.ico`, on the item and the title bar): `CSystemInfoDlg`, modal and resizable, read-only, no elevation needed: a tab per area over one list that shows the selected tab's rows (refilled on `TCN_SELCHANGE`; the list is raised above the tab control, which has `WS_CLIPSIBLINGS`, as the tab control painted over it otherwise), some grouped under titles drawn bold and shaded (as Page Files'), from WinSys `SystemDetails`: Operating System (product with the display version, edition, version with the UBR, build lab, installation type, architecture, the last feature update's install time, last boot (fast startup said) and uptime, computer and NetBIOS names, domain or workgroup, registered owner, locales), Computer (SMBIOS system, baseboard and BIOS, the firmware type), Processor (CPUID vendor, family, model and stepping, microcode, base speed, cores with the P/E split of a hybrid processor, logical processors, groups and NUMA nodes when more than one, caches, the hypervisor; virtualization and SLAT only without a hypervisor, as Windows then reports no SLAT; the features), Memory (installed, usable, slots used, then each populated slot's module under Modules) and Security (grouped: Boot, Virtualization-Based Security, Code Integrity, Credentials, Kernel, Speculative Execution, User Account Control; Secure Boot, VBS, memory integrity, the code integrity options, App Control, Smart App Control, Credential Guard (LsaIso running), LSA protection (the `RunAsPPL` value), the kernel debugger, kernel CET, Kernel DMA Protection, System Guard, KVA shadow and the speculation mitigations, MDS and BHI "Not affected" on AMD, which Windows reports nothing for, and UAC). Rows without a value are left out, and groups without rows. Refresh reads every tab again, keeping the tab and the selected row by name; Copy copies the selected row, or the tab's rows with `[Group]` titles, tab separated.
- **Firmware and TPM** (`FirmwareDlg.*`, System > Firmware and TPM...; the System menu (the Tools menu before, so its first command is still `ID_TOOLS_FIRMWARE`) is for dialogs that aren't tabs): `CFirmwareDlg`, modal and resizable (`CDpiDialogResize`), read-only, with a tab control over two panes shown and hidden by hand. Summary: the firmware type, Secure Boot and Setup Mode, the boot timeout, current and next entries and the boot entries in boot order (WinSys `Firmware`), and the TPM (WinSys `Tpm`), in sections drawn bold and shaded (custom draw). UEFI Variables: every variable (name, vendor GUID with a few known vendors named, attributes as NV/BS/RT..., size), sorted by name, the selected one's value as a hex dump in a read-only Consolas edit below. The variables need SeSystemEnvironmentPrivilege, so elevation; otherwise the summary and the status line say so. Refresh reads all again; Copy copies the summary (`[Section]` titles, tab-separated rows) or the selected variable with its dump. The tab control has `WS_CLIPSIBLINGS` and the panes are raised above it (`HWND_TOP`), as in the other tabbed dialogs: otherwise it can paint over them when the selection changes.
- **Computer menu** (after System, `CMainFrame::OnComputerCommand`, WinSys `Power`): Lock, Log Off, Sleep, Hibernate, Restart, Shut Down, Restart to Boot Options (Windows' advanced startup) and Restart to Firmware (the UEFI setup, as `shutdown /r /fw`). The ones that close programs (log off, the restarts, shut down) ask first, the button defaulting to Cancel; the settings are saved by `WM_ENDSESSION` as at any logoff. Sleep is enabled when the system has S1-S3 (not Modern Standby's S0, which `SetSuspendState` doesn't enter), Hibernate when it has S4 and a hibernation file, Restart to Firmware when elevated on UEFI firmware that offers booting to its setup; set once, at startup. A failure is reported.
- **Tools menu** (after Computer): Install Driver/Service... (`ID_TOOLS_INSTALLSERVICE`, `CMainFrame::OnInstallService`) runs the Services tab's `CServiceInstallDlg` (WinSys `ServiceManager::Install`) with its own title, a service by default (the type combo box chooses a driver); the status line names what was created, and the Services and Drivers tabs show it with their next refresh.
- **Memory lists** (System > Memory Lists, `CMainFrame::OnMemoryListCommand`): Empty Working Sets, Flush Modified List, Purge Standby List and Purge Low-Priority Standby List (WinSys `MemoryLists::Execute`), as RAMMap's Empty menu, each after a confirmation that says what it does; enabled only when elevated (SeProfileSingleProcessPrivilege); afterwards the status line has the free, standby and modified sizes before and after. The Performance tab's Memory page shows the lists in detail beside its graph when it's wide enough (`CPerfMemoryPage::m_Lists`, a plain report list whose rows are `ListRow`, texts set in place on every sample: zeroed, free, modified with its page-file and no-write parts, standby with each priority from 7 down, as RAMMap, and the pages repurposed from each since boot, and bad), from `PerfSample::Lists` (`MemoryLists::Read`, elevated only, as before; the composition bar is unchanged).
- **Pipes and Mailslots** (`PipesDlg.*`, System > Pipes and Mailslots..., `IDI_PIPE`, `pipe.ico`, on the menu item and the dialog's title bar): `CPipesDlg`, modal and resizable, read-only, no elevation needed: every named pipe and mailslot (WinSys `Pipes::EnumPipes`/`EnumMailslots`) in one list (kind, with `IDI_PIPE` or `IDI_MAILSLOT`, `mailbox.ico`, from an image list of the dialog's own in its small icon size; name, a pipe's current and maximum instances, creation time: only mailslots have one, as the named pipe file system reports no times), by name until a header is clicked (any column; ties by name), with a filter box above it (the name and the kind, as typed). Nothing is opened, as opening a pipe would connect to it. Copy copies the selected rows, or every row shown. The mailslots are appended to the pipes one by one: a range `insert` of the WinSys type warned C4530 under LTCG (see `winsys/CLAUDE.md` on exceptions).
- **Installed Packages** (`PackagesDlg.*`, System > Installed Packages..., `ID_SYSTEM_PACKAGES`, `IDI_PACKAGE` (`package.ico`) on the menu item and the title bar): `CPackagesDlg`, modal and resizable, read-only: the installed MSIX/AppX packages from WinSys `Packages::Enum` (about 1.3 s for 157 packages here, so read on a detached `std::thread` with COM initialized, MTA, which shares only a `LoadState` with the dialog and posts `WM_PACKAGES_READ`: closing doesn't wait; Refresh and All Users disabled meanwhile). The current user's by default; All Users (enabled only elevated: `FindPackages` needs it) reads every user's (190 here, as `Get-AppxPackage -AllUsers`). A row per package: name (the manifest's display name, else the package name), package name, version, architecture, kind (Main, Framework, Resource, Optional, Bundle; "(development)" for a registered loose layout), publisher (display name), signature kind (Store, System, Developer, Enterprise, None), status (OK or the `Package.Status` problems; such rows red), install date, running processes (the frame's snapshot by package full name, `ProcessInfoEx::GetPackageName`, gathered on the UI thread through a callback when the packages arrive), location, the dependencies' names and the full name. Frameworks and Resources (checked at first) shows those kinds too; the filter matches the display and package names, the publisher, the full name and the location; any column sorts (version, date and processes by value; the date and processes descending first). Launch (the menu's first item) starts the package's application through WinSys `Packages::Launch` (`IApplicationActivationManager::ActivateApplication`, as the Start menu does; it works from an elevated WinSysLive), the status line saying its PID, a message box why it failed; a package with several applications (`Packages::GetApplicationIds`, read when the menu opens) gets a submenu of their app IDs (Microsoft.M365Companions: People, Files, Calendar), one without any (frameworks, resources, another user's package) a grayed item; the menu is tracked with `TPM_RETURNCMD`, so the apps' items need no command IDs. Tested: Calculator launched from an elevated instance. Double-click or Open Folder opens the install folder; Go to Process (enabled while it runs) goes to its first process, closing the dialog; Copy (the selected rows, else all shown, with the column names), Copy Full Name. Counts checked against `Get-AppxPackage` (157 and 190); Go to Process tested on the Start menu's host.
- **Firewall Rules** (`FirewallDlg.*`, System > Firewall Rules..., `ID_SYSTEM_FIREWALL`, `IDI_FIREWALL` (`Firewall.ico`); its control IDs are `IDC_FWR_*`, as the Firmware dialog has `IDC_FW_*`): `CFirewallDlg`, modal and resizable: Windows Defender Firewall's rules from WinSys `Firewall::EnumRules` and the profiles from `Firewall::GetPolicy`, read on a detached `std::thread` (COM, MTA) that shares only a `LoadState` with the dialog and posts `WM_FIREWALL_READ` (closing doesn't wait). The profiles' line on top: each profile on or off with its default inbound and outbound actions ("all blocked" with Block All Inbound), the active ones said. A row per rule: name, group, direction, action, enabled, profiles, protocol (with ICMP types), local and remote ports (TCP and UDP only), addresses ("Any" for *), program, service ("(services)" for *), package SID, interface types, edge traversal and description; disabled rules gray, enabled block rules red (`NM_CUSTOMDRAW`). Inbound, Outbound (both on at first) and Enabled Only choose the rows; the filter matches the name, group, program, service, ports and description; any column sorts by its text. The list's context menu (`WM_CONTEXTMENU`, also from the keyboard; `TPM_RETURNCMD`): Enable Rule(s) and Disable Rule(s) (the selected ones that aren't already, through `Firewall::SetEnabled`, elevated only; each row updated in place, the status line counts them and says why any failed), Open File Location (the program with its environment variables expanded, Explorer selecting it), Go to Process (a running process whose image path is the program's: the frame's snapshot by lowercase path, gathered on the UI thread when the rules arrive; closing the dialog), Copy (the selected rows, else all shown, with the column names; also the Copy button). Checked against PowerShell: 784 rules, 472 inbound, 568 enabled, the same; a disabled test rule (an outbound block for a missing program, made with `New-NetFirewallRule` and removed after) was enabled from the keyboard's context menu and `Get-NetFirewallRule` saw it enabled.
- **COM Registration** (`ComRegistrationDlg.*`, System > COM Registration..., `ID_SYSTEM_COMREGISTRATION`, `IDI_COM` (`COM.ico`) on the menu item and the title bar; control IDs `IDC_CR_*`): `CComRegistrationDlg`, modal and resizable: the registered COM classes from WinSys `ComRegistry::EnumClasses`, the 64-bit and the 32-bit views (14,498 here, read in about 1.2 s on a detached `std::thread` (COM, MTA) that shares only a `LoadState` with the dialog and posts `WM_COMREG_READ`: closing doesn't wait), in an owner-data list (`LVS_OWNERDATA`, `LVN_GETDISPINFO`; `m_Rows` indexes the classes), each row's icon by where it runs (`ImageOf`: `IDI_MODULES` (`DLL.ico`) for in-process servers, surrogates and handlers, `IDI_COM_SERVER` (`Server.ico`) for local servers, `IDI_COM_SERVICE` (`service.ico`) for services, `IDI_OBJECT` (`Object.ico`) for the others; the dialog's own image list, shared with the list and made again for a new DPI). Columns: name, CLSID, ProgID, type (`ComRegistry::TypeText`), the server as registered ("(missing)" after a missing one), threading model, app ID and its name, service, Run As, registered (Machine, User, User (over machine), Package), view, the key's last write (Last Changed, sorted by time, newest first on the first click, the packaged classes, which have none, last), its TreatAs (with the target's name), Elevation ("Yes", or "Yes, without a prompt" for those in UAC's COMAutoApprovalList), and the server's signature, verified as its cell is first shown (`SignatureVerifier`, `WM_COMREG_SIGNED` repaints, those queued taken at once; "Checking..." meanwhile; `FileOf` puts a bare DLL name in the view's system folder and a 32-bit DLL's System32 in SysWOW64, not a local server's, which rpcss starts), and the package. The Concern column (`GetConcernText`) says why a row stands out, and its color (`GetConcern`) the worst of it: red for what someone could exploit or that runs other code (a machine-wide class's server a standard user can replace, or, missing, create: `ServerWritable`, 14 here, Zoom's Outlook plugin classes registered for the machine with their server in the user's AppData; a scriptlet, `ScriptletUrl`; a local server that runs an interpreter, `Interpreter`, but not rundll32 of a Windows DLL, as Windows' own `SHCreateLocalServerRunDll` servers are: Photo Viewer's rundll32 of a DLL in Program Files and mshta's HTML Application here; an invalid signature; a TreatAs to a per-user class, or to one whose server users can replace: `FindClass` looks the target up in `m_ByClsid`, HKCR's classes by CLSID and view), orange for a user's class over the machine's or a class the user's own ProgIDs point at where the machine's same ProgIDs point elsewhere (`RedirectedProgIds`: a ProgID hijack, which leaves the class's key alone), yellow for another per-user class (per-user classes are a known way to hijack a class), gray text for a missing server no standard user could create (a leftover, as old EdgeUpdate versions' proxies). Local Machine and Current User (both on at first) choose the hives (`InScope`): both, `HKCR`'s merged view (the user's class in place of the machine's it hides, `OverriddenByUser` left out: 14,498 here); one, that hive's own registrations (the machine's 14,428 with the 9 the user's hide, the user's 79). 32-bit Classes (on at first) and Suspicious Only (the colored and gray rows and those whose signature is known not to verify: 303 here) choose the rows too; the filter matches the name, CLSID, ProgID, server, app ID and its name, package, scriptlet, TreatAs and the redirected ProgIDs; the Concern column also notes a TreatAs to an unregistered class and an elevatable class with a replaceable or missing server; any column sorts by its text, empty values last either way (a thousand classes have no name). The context menu: Open File Location (Explorer with the file selected), Open in Registry Editor (also the double click; the class's key in HKLM or HKCU, under WOW6432Node for the 32-bit view, or its PackagedCom key, through `OpenRegistryEditor` in `RegistryEditor.*`, which the Registry tab uses too), Launch Permissions and Access Permissions ("(default)" when the app ID has none: `ComRegistry::GetPermission`, the machine's DefaultLaunchPermission or DefaultAccessPermission then; shown read-only in the system's ACL editor through `CComPermissionInfo`, an `ISecurityInformation` with dcomcnfg's rights (Local and Remote Launch and Activation, Local and Remote Access, each with COM_RIGHTS_EXECUTE) whose `SetSecurity` refuses; `CAclDialogTheming` darkens its dialogs; COM's built-in defaults when neither is set, said in a message box), Copy (the selected rows, or all shown, with the column names, in the header's order) and Copy CLSID. **Save...** writes the rows shown as CSV or tab-separated text (`ListExport::ToCsv`/`ToText`, `Save`: UTF-8 with a BOM), from the dialog's own text (`GetExportRows`), not the list's, which would queue every row's signature check; the signatures known so far go in. Ctrl+F from any of its controls puts the focus in the filter box with its text selected: the modal loop's messages go through a `WH_MSGFILTER` hook (`MSGF_DIALOGBOX`, installed in `WM_INITDIALOG`, removed in `WM_DESTROY`), as a dialog's controls get the keys and the frame's accelerators don't run. The status line, counting each class once as `HKCR` has it: the classes, the packaged ones, those a user could replace, the scripts and interpreters, the per-user ones and those over the machine's, the missing servers, and the rows shown.
- **DCOM and Running Objects** (`DcomDlg.*`, System > DCOM and Running Objects..., `ID_SYSTEM_DCOM`, `IDI_COM_SERVER` on the menu item, `IDI_COM` on the title bar; control IDs `IDC_DC_*`): `CDcomDlg`, modal and resizable, read-only, five tabs over one list and a details list (property and value) of the selected row, as the Kernel Callbacks dialog's (a table of cells per tab, sorted by any column: times and numbers as such, empty values last; the filter matches any cell). Everything is read on a detached thread (COM, MTA; about 2 s, mostly the classes) that shares only a `LoadState` and posts `WM_DCOM_READ`. **Machine**: WinSys `ComSecurity::GetMachineSettings`, orange when weaker than Windows' default; a permission's entries in the details ("Launch: Allow Everyone" - "Local Launch, Local Activation", broad remote grants noted). **App IDs**: `ComRegistry::EnumAppIds` (547 here) with Run As, service, surrogate, authentication level, Launch and Access (Set or Default), the classes using each (both views' `ComRegistry::EnumClasses`, a CLSID once), the executables and the last change; red for authentication level None (2 here), orange for a launch permission granting remote launch or activation to a broad account or an access permission granting remote access to Anonymous (10 here; Interactive's remote rights, in 70 app IDs, let no one in from outside and don't count), yellow for a stored account (Run As a user) or a per-user app ID; the details add the permissions' entries and the classes. **Elevation**: the classes with `Elevation\Enabled` (210 here), Without a Prompt for UAC's COMAutoApprovalList (163), red when a standard user can replace the server. **DCOM Errors**: the System log's DistributedCOM events of the last 30 days (`EventLog::Query` with the provider and the data), the class and app ID taken from the data's GUIDs (registered ones named; an unknown GUID is taken for the class), the user from a SID; events Windows logged without their insertion strings (the message is the template) say so. Successful activations can't be shown: no ETW provider reports them (see WinSys's docs). **Running Objects**: `ComSecurity::EnumRunningObjects` (Visual Studio's DTE and telemetry items and an open solution's file moniker here), a custom moniker's class (named) only, as a system moniker's says no more than its kind; the status line says what an elevated (or not) process sees. The context menu: Permissions (a machine permission) or Launch Permissions and Access Permissions (an app ID's own, else the machine's default), in the ACL editor through `ShowComPermissions` (`ComPermissionInfo.*`, moved out of the COM Registration dialog, which uses it too); Open in Registry Editor (the setting's key, the app ID's, the class's `Elevation` key; also the double-click, which opens a machine permission in the ACL editor instead); Open File Location (a class's server); Copy (also the button: the list that last had the focus, its selected rows or all). Tested: each tab filled, MachineLaunchRestriction's six entries in the details and in the ACL editor.
- **Virtual Machines and Containers** (`VirtualMachinesDlg.*`, System > Virtual Machines and Containers..., `ID_SYSTEM_VIRTUALMACHINES`, `IDI_VIRTUALMACHINE` (`res\VirtualMachine.ico`, on the menu item and the title bar); control IDs `IDC_VM_*`): `CVirtualMachinesDlg`, modal and resizable, one list of WinSys `VirtualMachines::Enumerate`'s systems as `VirtualMachineLookup` last read them (`VirtualMachineLookup.*`: its own `std::jthread`, COM in the MTA, shared with the Processes tab's column; `Refresh` posts `WM_VM_READ` to the dialog when a read ends). It asks for a read when it opens, on Refresh and every 2 seconds, and takes the processes from the frame's snapshot each time, so CPU follows the frame's updates. Columns: Name, Kind, State, CPU (the memory process's: Windows counts the virtual processors' time there, as Task Manager shows it), Processors, Memory (assigned), Worker PID, Memory Process (name and PID), Started (the worker's start), ID. The processes are matched as the column matches them (`VirtualMachineLookup::IdOf`). Sorted by any column (numbers and times as such), the selection kept by ID. The context menu offers Go to Worker Process and Go to Memory Process (closing the dialog; double-click is the worker, else the memory process) and Copy (also the button: the selected rows or all). The status line counts the systems and those with a worker, or says why they can't be read (not elevated: HCS and Hyper-V's WMI need an administrator). Tested here with two Hyper-V VMs running and four off or saved, WSL 2 and the Sandbox's template: all eight listed, with their memory processes; Go to Worker Process selected the right vmwp.exe.
- **Kernel Callbacks and Minifilters** (`KernelCallbacksDlg.*`, System > Kernel Callbacks and Minifilters..., `ID_SYSTEM_KERNELCALLBACKS`, `IDI_SYSTEM_DRIVER` on the menu item and the title bar; control IDs `IDC_KC_*`): `CKernelCallbacksDlg`, modal and resizable, read-only, from WinSys `KernelCallbacks`. Two tabs (Minifilters with `IDI_FILTER`, `Filter.ico`, Callback Registrations with `IDI_CALLBACK`, `callback.ico`: an image list of the dialog's own in the small icon size, destroyed with it, as a tab control doesn't) over one pair of lists (their columns set again on a tab change, as in Network Information; the lists and the filter raised above the tab control): Minifilters, the Filter Manager's filters by altitude, highest first (filter, altitude, instances, frame, type, company and description from the image's version, image path; administrator rights needed, said in the status line) above the selected filter's instances (drive letter, volume device, file system, instance, altitude, detached); Callback Registrations, the loaded drivers that import a registration function (driver, what it registers for, the number of imports, company, description, path, load order: the default order) above the selected driver's imports (function, library, kind, what it hooks). Security-relevant Only (on at first, shown on the second tab) keeps the drivers that register for processes, threads, images, the registry, handles (object callbacks), file systems, the network or boot drivers (46 of 140 here); the rest register for Plug and Play, power, bug checks and the like. The status line says that an import is what a driver can register, not what it did. The filter matches any cell of the upper list's rows and a driver's registration function names; both lists sort by any column (numbers, fractional altitudes too, as numbers); Copy copies the list that last had the focus (its selected rows, or all). Go to Driver (the button, a double-click, the upper list's context menu) ends the dialog with `IDC_KC_GOTO` and the frame calls `GoToKernelModule` with `GetDriverPath`. Loading takes about half a second (every module's file is parsed), on the UI thread under a wait cursor.
- **Certificate Stores** (`CertificatesDlg.*`, System > Certificate Stores..., `ID_SYSTEM_CERTIFICATES`, `IDI_CERTIFICATES` (`Certificates.ico`) on the menu item and the title bar (the stores in the tree keep `IDI_KEY`); control IDs `IDC_CE_*`): `CCertificatesDlg`, modal and resizable, read-only, from WinSys `Certificates`: a tree of the Local Machine's and the Current User's stores (`IDI_SYSINFO`, added to the frame's image list for it, and `IDI_USER`; each store by its localized name with its count and how many are of concern; at first the machine's Trusted Root Certification Authorities; scrolled back to the left after filling, as `EnsureVisible` scrolls a long name in sideways) beside the selected store's certificates, or a whole location's: issued to and by, expiry, the concern (`Certificates::Assess`), the store, the source (the physical store as certmgr names it: Registry, Group Policy, Enterprise, Third-Party, Smart Card, Windows Insider), added, intended purposes (`<All>` for any), friendly name, key, signature, private key, valid from, thumbprint, serial number. Rows are colored by the concern as the COM Registration dialog's: red (a trusted root with its private key here, or a trusted certificate on Microsoft's disallowed list), orange (a root not in Microsoft's root program), yellow (added in the last 30 days where trust is granted), gray text (expired).
